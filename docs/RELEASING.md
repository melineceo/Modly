# Выпуск новой версии Modly

Выпуск — это четыре файла на странице [Releases](https://github.com/melineceo/Modly/releases):

| Файл | Что это |
|---|---|
| `ModlySetup-<версия>.exe` | установщик: внутри архив выпуска |
| `Modly-<версия>-windows-x64.zip` | архив: портативная версия и пакет обновления (`Modly/modly.exe`, `Modly/modly-updater.exe`, лицензия, README) |
| `modly-update.json` | манифест: версия, что нового, размер и SHA-256 архива и установщика |
| `modly-update.json.sig` | подпись манифеста ключом выпусков (Ed25519, hex) |

Установленный Modly берёт с GitHub список выпусков, скачивает манифест и подпись, проверяет подпись
открытым ключом, вшитым в программу (`PUBLIC_KEYS` в `crates/modly-core/src/update.rs`), и только потом
качает архив и сверяет его SHA-256 с манифестом. Ставит обновление `modly-updater.exe` из самого архива:
ждёт, пока Modly закроется, меняет файлы (старые — в `.modly-old`), запускает новый Modly и, если тот
сразу упал, возвращает старые файлы.

## Ключ подписи

Закрытый ключ — `%USERPROFILE%\.modly\release-signing-key.txt` (или путь в `MODLY_SIGNING_KEY`).
Он создаётся один раз командой `cargo xtask keygen` и **никогда не попадает в репозиторий**.
Сохраните резервную копию в надёжном месте: без ключа нельзя выпустить обновление, которое примут
уже установленные копии Modly.

Сменить ключ: добавьте новый открытый ключ в `PUBLIC_KEYS` рядом со старым, выпустите версию, подписанную
**старым** ключом, — и только после этого подписывайте выпуски новым (старый ключ можно убрать позже).

## Как выпустить

1. Поднимите версию в `Cargo.toml` (`[workspace.package] version`, например `0.3.0-beta` или `1.0.0`).
   Версия с `-` (`-beta`, `-rc.1`) выходит как pre-release и приходит только тем, у кого включены бета-версии.
2. Опишите изменения в `CHANGELOG.md`: раздел `## <версия> — <дата>` с подразделами `### Русский` и `### English`.
3. Закоммитьте и отправьте на GitHub (`git push`).
4. Соберите и проверьте выпуск:
   ```
   cargo xtask dist
   ```
   В `target/dist` появятся установщик, архив, манифест с подписью, `SHA256SUMS.txt` и `release-notes.md`.
   Xtask сам проверяет, что подпись подходит к ключу, вшитому в Modly.
5. Выложите:
   ```
   cargo xtask dist --publish
   ```
   Нужен GitHub CLI (`gh auth login`). Xtask откажется публиковать, если в репозитории есть
   незакоммиченные изменения или коммит ещё не на GitHub.
6. Обновите ссылку «Скачать Modly» на сайте (`HM_MODLY_DOWNLOAD_URL` в `app/config.local.php` сайта модов):
   страница `…/releases/tag/v<версия>` (ссылка `/releases/latest` пропускает pre-release).

## Проверка без GitHub

- `MODLY_SETUP_SANDBOX=<папка>` — установщик и удаление пишут ярлыки в эту папку, а записи реестра —
  в `HKCU\Software\ModlySandbox`; ссылки `modly://` не трогаются. Вместе с `MODLY_HOME=<папка>` настоящие
  данные Modly не задеваются.
- `MODLY_UPDATE_API=http://127.0.0.1:<порт>` — Modly и обновлятор берут список выпусков с локального
  сервера в формате GitHub API (`/repos/melineceo/Modly/releases`). Подпись всё равно проверяется вшитым
  ключом, так что подменить пакет так нельзя.
- `cargo xtask dist` с `CARGO_TARGET_DIR=target/e2e` собирает вторую версию отдельно — удобно, чтобы проверить
  обновление «старая → новая».
