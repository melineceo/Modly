# Пакет мода: `modly.json`

Пакет мода — папка с файлом `modly.json` и файлами мода. Modly ищет пакеты в:

- `%APPDATA%\Modly\mods\<папка мода>`;
- `mods\` рядом с `modly.exe`;
- папках, добавленных в **Настройки → Папки модов** (сама папка с `modly.json` или папка с пакетами внутри).

По пакету Modly **находит игру на диске**, показывает мод на её странице и **ставит / обновляет / удаляет**
его одной кнопкой. Связь с работающим модом (переключатели, ползунки) — отдельно, через
[протокол](PROTOCOL.md); пакету она не нужна, а мод с SDK работает и без пакета.

## Пример

```json
{
  "id": "my-mod",
  "name": "My Mod",
  "version": "1.0.0",
  "author": "me",
  "description": { "en": "Cheats for My Game", "ru": "Читы для My Game" },
  "links": { "site": "https://example.com" },
  "game": {
    "id": "my-game",
    "name": "My Game",
    "exe": "MyGame.exe",
    "detect": ["{managed}/Assembly-CSharp.dll"],
    "accent": "#7c5cff"
  },
  "install": {
    "method": "unity-mono",
    "assembly": "bin/MyMod.dll",
    "entry": "MyMod.ModEntry.Init"
  },
  "dev": { "build": "powershell -NoProfile -ExecutionPolicy Bypass -File build.ps1" }
}
```

## Поля

| Поле | | |
|---|---|---|
| `id` | обязательно | постоянный идентификатор (совпадает с `mod.id` в `hello`, если мод использует SDK) |
| `name` | обязательно | название |
| `version` | | версия для показа |
| `version_from` | | взять версию из исходников: `{"file": "src/ModEntry.cs", "after": "Version = \""}` — версия это текст после `after` до ближайшей кавычки |
| `author`, `description`, `links` | | для карточки мода; `description` — строка или переводы |
| `game` | обязательно | для какой игры мод, см. ниже |
| `install` | обязательно | как ставить, см. ниже |
| `dev.build` | | команда сборки (выполняется через `cmd /C` в папке пакета). Кнопка «Собрать» появляется в режиме разработчика |
| `maps` | | карты игры: сама карта или путь к JSON-файлу в пакете, см. [ниже](#maps--карты-игры) |

### `game`

| Поле | | |
|---|---|---|
| `id` | обязательно | идентификатор игры, например `family-time-ep3` (лучше такой же, как у других модов для этой игры) |
| `name` | обязательно | название |
| `exe` | обязательно | имя exe игры |
| `detect` | | файлы, которые должны лежать рядом с exe (с подстановками) — чтобы не перепутать с другой игрой с таким же exe |
| `accent` | | цвет обложки; по умолчанию — из иконки игры |
| `steam_appid` | | номер игры в Steam (`https://store.steampowered.com/app/<номер>`). Копия из Steam с этим номером и этим `exe` — та же игра, даже если файлов из `detect` в ней нет |
| `builds` | | сборки игры, на которых мод проверен: `[{"name": "b108", "sha256": "…"}]`, см. ниже |
| `build_file` | | файл, по которому узнаётся сборка (с подстановками). По умолчанию — код игры: `{managed}/Assembly-CSharp.dll` для Unity Mono, `GameAssembly.dll` для IL2CPP, иначе сам exe |

Modly ищет папки с этим exe и файлами `detect` на рабочем столе, в загрузках, документах, в папках
`Games`/`Игры` и `Program Files` на дисках, в папках прямо в корне дисков (`D:\Игра`), в библиотеках Steam
и itch — и добавляет их в библиотеку. Копия не из Steam (из другого магазина, переносная) находится так же — по exe
и `detect`; игру в другом месте можно добавить кнопкой «Добавить игру». Каждая копия игры
— отдельная запись: мод можно поставить в одну копию и не ставить в другую. Мод относится к копии по
её **папке** (exe и `detect`, у Steam — ещё и `steam_appid`), а не по `id`: если два автора назвали одну
игру по-разному, моды обоих видны на её странице.

#### Сборки игры (`builds`)

Игры обновляются, и мод, сделанный для одной сборки, может сломаться в следующей. В `builds` перечислите
сборки, на которых вы мод проверили. Modly считает SHA-256 файла `build_file` у каждой копии игры и пишет
на карточке мода «Сборка игры b108 — проверена автором мода» или предупреждает: «Эту сборку игры автор мода
не проверял — мод может не работать». Это предупреждение, а не запрет: установить мод можно в любую сборку.

Отпечаток считать руками не нужно: включите **Настройки → Режим разработчика**, откройте страницу игры —
на карточке мода появится кнопка **«Добавить сборку в modly.json»**. Название Modly возьмёт из папки игры
(`…_DX12_b108` → `b108`, `Game v1.4.2` → `v1.4.2`), его можно поменять. Modly перезапишет `modly.json`
в стандартном оформлении (отступ — два пробела).

Копии одной сборки для разных DirectX (DX11 и DX12) обычно с одинаковым кодом — отпечаток у них один.

```json
"game": {
  "id": "family-time-ep3",
  "name": "Family Time Ep.3",
  "exe": "FamilyTime.exe",
  "detect": ["{managed}/Assembly-CSharp.dll", "{data}/app.info"],
  "builds": [
    { "name": "b102", "sha256": "…64 знака…" },
    { "name": "b108", "sha256": "…64 знака…" }
  ]
}
```

### Пути

Все пути в `modly.json` — относительные: внутри пакета (`assembly`, `files[].from`) и внутри папки игры
(`files[].to`, `cleanup`). `..`, диски (`C:`), `\\сервер` и `/` в начале запрещены — пакет с таким путём
Modly не загрузит. Это важно, потому что пакеты приходят и из каталога сайта.

### Пакет в каталоге mods.hackerstone.xyz

Загрузите в «Студии» на сайте ZIP, где `modly.json` лежит в корне архива или в единственной папке верхнего
уровня. После проверки модератором у мода появляются кнопки «Установить через Modly» на сайте и
«Установить» в каталоге Modly: Modly скачивает архив, сверяет SHA-256, распаковывает его в
`%APPDATA%\Modly\mods\<id>` и ставит мод во все найденные копии игры.

### Подстановки в путях игры

| | |
|---|---|
| `{data}` | папка данных Unity: `<ИмяExe>_Data` |
| `{managed}` | `{data}/Managed` |
| `{plugins}` | `BepInEx/plugins` |

### `maps` — карты игры

Карты, которые Modly покажет на странице игры и во вкладке «Карта» оверлея — даже без запущенной игры.
Запись — сама карта (те же поля, что у сообщения `map` в [протоколе](PROTOCOL.md#карты)) или путь
к JSON-файлу с ней внутри пакета. Картинка — путь внутри пакета (PNG, JPEG или WebP, до 32 МБ).

```json
"maps": [
  "maps/world.json",
  { "id": "cave", "title": "Cave", "image": "maps/cave.png",
    "markers": [ { "id": "exit", "x": 120, "y": 40, "title": "Exit" } ] }
]
```

Если мод подключён и прислал карту с тем же `id`, Modly показывает её — с живыми метками и действиями.
Подробно — [Карта в своём моде](https://mods.hackerstone.xyz/docs.php?p=mod-maps).

## Способы установки (`install.method`)

### `unity-mono` — Unity без загрузчиков

Для игр на Unity с Mono (`<Игра>_Data/Managed/Assembly-CSharp.dll`). BepInEx и прочие загрузчики
не нужны: Modly кладёт DLL в `Managed` и прописывает её в `ScriptingAssemblies.json` и
`RuntimeInitializeOnLoads.json` — Unity сама загружает мод и вызывает указанный метод при старте.
Оригиналы файлов сохраняются как `*.orig`.

| Поле | | |
|---|---|---|
| `assembly` | обязательно | путь к DLL в пакете |
| `entry` | обязательно | `Пространство.Класс.Метод` — `public static void` без параметров |
| `load` | `after-scene` | когда вызвать: `after-scene`, `before-scene`, `after-assemblies` |
| `files` | | дополнительные файлы: `[{"from": "в пакете", "to": "в игре"}]` |
| `cleanup` | | что удалить при удалении мода (файлы, можно `*` в имени: `{data}/Saves/*.mymod`) |
| `legacy` | | старые версии мода под другими именами: `[{"assembly": "OldMod.dll", "entry": "OldMod.Entry.Init"}]` — убираются при установке |

Точка входа обычно создаёт `GameObject` со своим `MonoBehaviour` — см. пример
[`examples/unity-mod`](../examples/unity-mod).

> Сборка мода ссылается на DLL самой игры (`Managed/*.dll`) с `-nostdlib`: в сборках игр часть .NET
> вырезана, и так компилятор сразу покажет, чего в этой игре нет.

### `files` — просто скопировать файлы

Для плагинов BepInEx/MelonLoader, pak-модов Unreal (`Content/Paks/~mods`), конфигов и всего остального.

```json
"install": {
  "method": "files",
  "files": [
    { "from": "MyPlugin.dll", "to": "{plugins}/MyPlugin.dll" }
  ],
  "cleanup": ["BepInEx/config/my-plugin.cfg"]
}
```

## Состояние мода

Modly определяет состояние **по файлам игры**, а не по своим записям — мод, поставленный другим
способом (например, своим `.bat`), тоже виден:

| | |
|---|---|
| Не установлен | файлов мода в игре нет |
| Установлен | файлы на месте и совпадают с пакетом |
| Есть обновление | файлы на месте, но отличаются от пакета (пакет новее — например, мод пересобран) |
| Повреждён | установлен частично (например, DLL есть, а в `ScriptingAssemblies.json` её нет) |
| Не собран | в пакете нет файлов для установки (нажмите «Собрать» или соберите мод сами) |
